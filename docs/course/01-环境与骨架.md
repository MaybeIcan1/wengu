## 💣 本阶段踩坑实录（每条都是一个知识点）

| 坑 | 根因 | 一句话解法 |
|---|---|---|
| IDEA 没有 Maven 面板/运行箭头 | pom 未链接进工程 | 右键 `pom.xml` → **Add as Maven Project** |
| import 全爆红 | 依赖导入成功但编辑器缓存未刷新 | Build → Rebuild；不行 Invalidate Caches+Restart |
| 重启后打开的是 `untitled` | IDEA 恢复最近项目 | 欢迎页认准 `wengu`，顺手删掉旧的 untitled 项目 |
| New Module 找不到 Spring Initializr | IDEA 新版改名 | 就叫 **Spring Boot**（底层同 start.spring.io） |
| npm 面板不见 | package.json 未登记 | 打开 package.json → **Attach npm project**（或 scripts 区块绿箭头直接跑） |
| docker pull 全失败 | ①Hub 被墙 ②系统代理幽灵 | daemon.json 配镜像源 + Docker 代理模式改 Manual 留空（脱离死掉的 Clash 系统代理 127.0.0.1:7890） |
| `docker ps` 看不到容器 | ps 只显示运行中 | 看 `docker ps -a`；`docker start 六个名字` 才会运行 |
| git 大量 LF/CRLF warning | Windows 换行符自动转换 | 无害忽略，概念见下「关联八股」 |

## 🔬 事故复盘：Docker 数据盘迁移（值得单独一篇的实战）

**背景**：想把 4.6GB 的 `docker_data.vhdx`（镜像/容器/卷唯一载体）从 C 盘迁到 D 盘。

**事故时间线**：
1. GUI 点 Disk image location → Apply → 恰逢 Docker Desktop 自动更新安装，更新中断并失败 → 配置未保存
2. AI 手工路线：robocopy 搬 vhdx + 改 WSL 注册表 BasePath + 手写 settings DataFolder → **升级后的 4.74 启动时把发行版重新注册回 C 默认路径，并新建了一个空数据盘** → 引擎"失忆"（镜像/容器骤然消失，实际数据无损躺在 D）
3. 恢复：靠日志定位（`provisioning data via data disk with id` 与盘内 id 比对确认引擎认领了老盘）→ 数据回 C → **真备份**（robocopy C→D）→ 正常启动，5 镜像 6 容器全部找回
4. 最终正解：**Docker 健康状态下用官方 GUI 迁移**（Settings → Resources → Advanced → Disk image location → Apply）→ 原子搬家成功，C 盘清零，新家 `D:\Docker\data\DockerDesktopWSL\`

**三条铁律**：
1. **手工搬 vhdx = 版本兼容赌博**，升级后 Docker 可能不认旧注册路径
2. 动任何存储之前**先备份**（并且备份命令要真的执行成功——本次第一次"备份"因为源文件名已搬走而复制了个空，靠复盘核对才发现）
3. 迁移这种系统级操作交给产品自己的官方机制，不要用文件级 trick

**关联知识**：Docker Desktop on Windows = WSL2 发行版 + 一个数据 vhdx；镜像/容器层/命名卷全在这一个文件里；vhdx 只涨不缩（删除镜像不会自动缩小文件）。
